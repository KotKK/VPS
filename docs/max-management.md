# Управление AmneziaWG через MAX

Бот предоставляет меню «Клиенты», «Статус», «Добавить клиента», «Удалить клиента»,
«Панель». После выбора клиента доступны исходный файл `.conf` и QR-код AmneziaWG.
Удаление требует отдельного подтверждения; «Отмена» завершает текущий диалог.
Создание сразу открывает кнопки скачивания. Список клиентов разбит на страницы.
Добавление и настройка зарубежных VPS остаются в веб-панели.

В MAX нет аналога постоянной reply-клавиатуры Telegram. Главное меню доступно
через `/menu`; команды `/clients`, `/status`, `/add_client`, `/delete_client`,
`/panel`, `/cancel` добавляются в системное меню MAX с русскими описаниями.
На iPhone меню открывается кнопкой «/» внизу справа, на остальных платформах
подсказки команд доступны при вводе `/`. Кнопки действий остаются под сообщениями.

## Как работает

- MAX отправляет события на HTTPS `/max/webhook`, порт 443.
- Отдельный nginx virtual host проксирует только этот POST-маршрут на
  `127.0.0.1:8081`. Панель `127.0.0.1:8080` остаётся доступной через SSH.
- Подпись-заголовок `X-Max-Bot-Api-Secret` проверяется до чтения события.
  Выполняются команды только заданного `MAX_USER_ID` в заданном личном
  `MAX_CHAT_ID`. Группы и остальные пользователи игнорируются.
- События сохраняются в `max-events.sqlite3` перед HTTP 200. Отдельный поток
  выполняет команды последовательно. Повторная доставка одного сообщения
  или callback не выполняет действие повторно. Кнопки старого меню отклоняются.
- После сбоя процесса начатая команда не выполняется повторно автоматически:
  проверьте её результат в панели и откройте `/start`. Не начатые события
  остаются в очереди. Меню после перезапуска начинается заново.
- У MAX своя очередь `max-notifications.sqlite3`, у Telegram сохраняется
  прежняя `notifications.sqlite3`. Доставка в один канал не подтверждает
  доставку в другой. MAX обращается к API напрямую из России и может сообщить
  об отказе всех зарубежных VPS. Ошибки доставки повторяются health-таймером.
- Код бота и webhook размещаются на российском шлюзе. При настройке физический
  интерфейс основного маршрута сохраняется как `MAX_DIRECT_INTERFACE`. Все HTTPS
  запросы MAX, включая файлы и QR-коды, используют `SO_BINDTODEVICE` для этого
  интерфейса. Прокси из окружения и системные прокси игнорируются. При отказе
  интерфейса запроса через VPN не будет: отправка завершится ошибкой и останется
  в очереди. Имена интерфейсов AWG/WG/TUN/TAP отклоняются.
- Уведомления об установке VPS, отказах и восстановлении берутся из существующего
  мониторинга; повторных проверок и изменений VPN-маршрутизации не добавляется.

## Установка

1. Скопируйте новые модули `gateway/app/max_*.py` и обновлённый `notifications.py`
   в `/opt/awg-gateway/gateway/app/`.
2. Установите `gateway/deploy/systemd/gateway-max.service` в
   `/etc/systemd/system/`, выполните `systemctl daemon-reload`.
3. Подготовьте имя VPS, доступное из интернета. При отсутствии собственного
   домена можно использовать `awg-max-<IP-с-дефисами>.sslip.io`.
   Бесплатное DNS-имя зависит от доступности стороннего DNS-сервиса.
4. Создайте отдельный nginx virtual host и выпустите доверенный сертификат
   Certbot. Используйте `gateway/deploy/max.nginx.conf` как пример, заменив
   имя и пути сертификатов. На этапе выдачи сертификата нужен только HTTP-блок
   с webroot `/var/www/awg-max-acme`. HTTPS-блок включайте после выпуска.
   Продление сертификата должно перезагружать nginx через deploy hook.
5. API MAX использует сертификат НУЦ. Загрузите корневой сертификат из
   официального источника в `/etc/awg-gateway/max-ca.pem`, права 0600.
   Он добавляется к доверию только клиента MAX, системное хранилище не меняется.
6. В интерактивном SSH-терминале от root:

   ```bash
   cd /opt/awg-gateway
   .venv/bin/python -m gateway.app.max_setup
   ```

   Укажите HTTPS-адрес `/max/webhook`, введите токен скрытым вводом, затем
   отправьте показанный одноразовый код боту в личном чате. ID аккаунта и чата
   определятся автоматически. Long Polling применяется только во время привязки;
   затем создаётся webhook. Чужая существующая подписка не удаляется.

Настройка сохраняет MAX-переменные в `/etc/awg-gateway/secrets.env` атомарно
с правами 0600, сохраняя остальные настройки. Включает `gateway-max`, перезапускает
панель для подключения нового канала уведомлений. Telegram продолжает работать.

## Проверка

```bash
systemctl status gateway-max --no-pager
journalctl -u gateway-max -n 40 --no-pager
systemctl status gateway-health.timer --no-pager
```

В личном чате отправьте `/start`, проверьте список клиентов, файл, QR, статусы
всех VPS, отмену создания и отмену удаления. Не публикуйте `secrets.env`, файлы
клиентов и QR-коды: они содержат данные доступа.
