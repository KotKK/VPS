# Распределение клиентов по VPS

Каждый клиент закрепляется за одним доступным зарубежным VPS. Новые и
переключаемые клиенты назначаются серверу с минимальным числом клиентов.
Это распределение по количеству устройств, а не выравнивание скорости/байтов.
После восстановления или добавления выхода клиенты перераспределяются
между доступными VPS. Разница в количестве клиентов составляет максимум
одного клиента. Переключается только необходимое для выравнивания число устройств.
При неизменном сбалансированном пуле назначения сохраняются.
Назначения хранятся в `/var/lib/awg-gateway/routing.sqlite3` и сохраняются
при перезапуске панели и шлюза. На странице «Клиенты» показаны название и IP
назначенного VPS.

`gateway-health.timer` проверяет серверы примерно раз в минуту. Если handshake
устарел или HTTPS-проверки трёх разных адресов завершились ошибкой, монитор исключает VPS
из маршрутизации и переназначает только его клиентов. Обнаружение не мгновенное:
к интервалу таймера добавляется время проверок. Активные соединения при смене
внешнего IP могут оборваться; устройство сохраняет прежний VPN-профиль.
При наличии рабочего выхода VPS возвращается в пул после трёх успешных
циклов подряд. Если все выходы недоступны, первый ответивший сервер возвращается
сразу. После возвращения VPS выполняется перераспределение клиентов.
Открытые соединения переключённых устройств могут переподключиться.
Ежедневной принудительной смены сервера нет.

Если все серверы недоступны, клиентский транзит блокируется. Прямого выхода
через российский сервер нет. Неизвестные клиентские адреса также блокируются.
Локальные сервисы самого шлюза остаются доступны.

Единый контроллер маршрутизации вызывается панелью при изменении VPS/клиентов,
монитором после обновления состояния всех VPS и службой
`gateway-client-routing.service` при загрузке. SQLite-транзакция сериализует
изменения между процессами. Назначения публикуются только после успешного
применения маршрутов и атомарной загрузки nftables. Старыe правила firewall
первого VPS заменяются в той же транзакции nftables.

Установка службы восстановления (из `/opt/awg-gateway`):

```sh
install -m 0644 gateway/deploy/systemd/gateway-client-routing.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now gateway-client-routing.service
```

Для ручной проверки/восстановления правил без перезапуска VPN-интерфейсов:

```sh
cd /opt/awg-gateway
.venv/bin/python -m gateway.app.client_routing
nft list table inet awg_gateway
```
