# Автоматическое добавление зарубежных VPS через панель

## Цель

Администратор добавляет чистый зарубежный VPS с Debian 13 через закрытую веб-панель российского шлюза. Он вводит название, IPv4-адрес и пароль `root`; панель самостоятельно устанавливает AmneziaWG, создаёт туннель, проверяет выход в интернет и подключает узел к балансировке. Настройки клиентских устройств при добавлении или удалении выходов не меняются.

## Ограничения

- Панель доступна только через SSH-туннель на `127.0.0.1:8080`.
- Поддерживаемая удалённая ОС на первом этапе — чистая Debian 13.
- SSH-логин всегда `root`, аутентификация выполняется временным паролем.
- Пароль существует только в памяти фоновой задачи и не записывается в SQLite, HTML, журналы или исключения.
- Первый SSH host key принимается по модели TOFU (`StrictHostKeyChecking=accept-new`); изменение уже известного ключа блокирует подключение.
- Узел входит в балансировку только после успешной полной проверки.

## Пользовательский поток

Форма добавления содержит название, IPv4-адрес, неизменяемый логин `root` и пароль. «Отмена» до отправки не создаёт задачу и возвращает пользователя к списку.

После отправки панель немедленно создаёт запись VPS и запускает фоновую задачу. В списке отображаются этапы:

1. подключение по SSH;
2. проверка Debian 13;
3. установка пакетов AmneziaWG;
4. настройка удалённого `awg-exit`, маршрутизации и NAT;
5. настройка отдельного локального uplink;
6. проверка handshake и доступа в интернет;
7. подключение к балансировке.

Итоговые состояния: `Установка`, `Доступен`, `Ошибка`, `Удаляется`. Для установки доступна команда «Остановить установку», применяемая между этапами. Для состояния `Ошибка` доступны «Повторить» и «Удалить». Повтор имени или IP отклоняется до запуска SSH.

## Компоненты

### Постоянное хранилище

SQLite-хранилище содержит идентификатор, название, IP, состояние, текущий этап, безопасное описание ошибки, выделенные номера интерфейса/таблицы/подсети и временные метки. Оно не содержит SSH-пароль и приватные ключи.

Состояние загружается при каждом старте панели. Записи в состоянии `Установка` после аварийного перезапуска переводятся в `Ошибка` с возможностью безопасного повторного запуска. Сетевые идентификаторы выделяются транзакционно и не переиспользуются, пока предыдущая операция удаления не завершена.

### Очередь фоновых задач

Внутрипроцессный исполнитель выполняет не более одной сетевой операции одновременно. Это исключает гонки при обновлении общих правил балансировки. HTTP-обработчик создаёт запись и возвращает перенаправление, не удерживая соединение браузера до завершения установки.

Каждый этап проверяет флаг отмены. Остановка выполняет локальный откат созданных интерфейсов, маршрутов и незавершённой записи; уже выполненную удалённую настройку можно безопасно удалить повторной идемпотентной командой.

### SSH-транспорт

Транспорт принимает типизированный запрос с IP, `root` и секретом в памяти. Команды передаются без включения пароля в командную строку. Вывод очищается от чувствительных значений перед записью в журнал. Ограничиваются время подключения, общий срок этапа и размер вывода.

Удалённые скрипты проверяют ОС, устанавливают только необходимые пакеты, создают ключи с правами `0600`, включают forwarding, формируют systemd units и nftables-правила. Все операции идемпотентны.

### Конфигурация туннелей

Каждый зарубежный VPS получает отдельный локальный AWG-интерфейс, уникальную /30-подсеть, UDP-порт, route table и fwmark. Приватные ключи остаются на соответствующих серверах. Публичные ключи и несекретные сетевые параметры сохраняются в состоянии.

После настройки обеих сторон provisioner ждёт handshake, затем проверяет доступ в интернет с исходящим интерфейсом нового uplink. Только после обеих проверок узел получает статус `Доступен`.

### Балансировка

Генератор конфигурации строит правила только из узлов со статусом `Доступен`. Для новых соединений используется равномерный выбор выхода; существующий поток сохраняет один выход через connection mark. Адреса SSH и AWG endpoint всех выходов исключаются из маркировки, чтобы не возникал маршрутный цикл.

Изменения применяются атомарно: новая конфигурация сначала проверяется, затем заменяет текущую. Если применение не удалось, сохраняется последняя рабочая конфигурация, а новый VPS остаётся в состоянии `Ошибка` и не получает клиентский трафик.

## Удаление

Перед удалением доступный VPS исключается из балансировки и применяется новая рабочая конфигурация. Затем удаляются локальные интерфейс, маршруты, unit и несекретная запись состояния. Если удалённый сервер доступен, provisioner удаляет его AWG-конфигурацию и связанные nftables-правила. Недоступность удалённого VPS не возвращает его в балансировку и отображается как предупреждение о неполной удалённой очистке.

Удаление последнего доступного выхода требует отдельного подтверждения. До подтверждения никаких сетевых изменений не выполняется.

## Ошибки и безопасность

Пользователь получает русское сообщение для неверного пароля, изменившегося host key, неподдерживаемой ОС, ошибки установки пакетов, отсутствия handshake, отсутствия интернета и ошибки применения балансировки. Техническая причина сохраняется в очищенном виде.

Приложение не передаёт введённые значения оболочке как составную строку: аргументы команд формируются списками, а удалённые конфигурации передаются через стандартный ввод. Имена валидируются существующим безопасным правилом, IP — как IPv4. CSRF и дополнительная аутентификация не добавляются, поскольку панель остаётся loopback-only за индивидуальным SSH-туннелем.

## Проверки

- Модульные тесты: валидация, распределение сетевых идентификаторов, переходы состояний, отмена и безопасная очистка ошибок.
- Интеграционные тесты: HTTP-поток с поддельным SSH-транспортом, успешная установка, ошибка каждого этапа, повтор, остановка и удаление.
- Тесты идемпотентности: повторный запуск не создаёт второй интерфейс и не повреждает готовый узел.
- Тесты балансировки: один выход, два выхода, исключение недоступного выхода, атомарный откат.
- Тесты секретов: пароль отсутствует в базе, HTML, логах и исключениях.
- Проверка на сервере: handshake, внешний IP через новый интерфейс, распределение новых соединений и восстановление списка после перезапуска панели.

## Критерии готовности

Функция готова, когда чистый Debian 13 VPS добавляется из панели без ручного входа на него, становится доступным только после сетевой проверки, участвует в балансировке, переживает перезапуск панели и безопасно удаляется. Клиентские конфигурации при этом остаются неизменными, а SSH-пароль нигде не сохраняется.
